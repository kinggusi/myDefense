## 구현

- `DamagePayload`에 세션, Runtime Projectile/Target, Mutation 메타데이터와 유한·양수 피해 검증을 추가했다.
- `HitEvent`를 추가해 State Authority가 수락한 Hit의 식별자와 Tick을 보존한다.
- `AlienAttackSnapshot.FromCalculatedStats`는 이미 계산된 StatCalculator 결과만 스냅샷으로 만든다.
- `UnitAttack`의 Target Search와 발사는 Fusion Battle에서 State Authority만 수행하며, canonical Skill/Projectile 연결을 통해 Network Projectile을 생성한다.
- 네트워크 Projectile은 State Authority에서만 이동·추적·충돌·피해·Despawn하고, canonical ProjectileSpec, RuntimeProjectileId, 대상별 중복 Hit, Pierce/Lifetime 정책을 유지한다.
- Kill Deduplicator와 BattleSummary에 Support Kill 통계를 추가했다. Support Kill은 Gold을 변경하지 않는다.
- `MonsterStat`는 NaN/Infinity/0 이하 DamagePayload를 거부한다.

## 리뷰 및 잔여 검증

독립 리뷰는 조건부 PASS였으며 P0 결함은 없었다. 다음은 실제 Fusion 2클라이언트 수동 검증 대상이다.

- Projectile Spawn 및 NetworkTransform 동기화
- Monster 충돌 피해와 State Authority 단독 적용
- 동일 대상 중복 Hit, Pierce, DestroyOnHit
- Lifetime 만료 Despawn
- Support Kill 장부 기록 및 Gold 비변경

P0-8-2는 Spring canonical Battle Entry API가 영구 Alien 레벨과 `AlienStatCalculator` 결과를 제공하고, Fusion State Authority가 manifest/version 및 유한·양수 필드를 검증해 runtime Unit에 주입하도록 완성했다. ACTIVE Mutation은 권위 상태와 함께 snapshot에 재적용되며, Fusion 전투는 유효 snapshot 전에는 공격하지 않는다. 실제 Host/Standalone Client에서 player별 48종 catalog 로드와 Kidnap 후 snapshot 적용을 확인했다.

잔여 위험은 프로젝트 인증 계층 부재에 따른 username spoof 가능성(릴리스 전 principal 바인딩 필요)과 catalog HTTP 실패 후 현재 세션에서 재시도하지 않는 fault latch다.

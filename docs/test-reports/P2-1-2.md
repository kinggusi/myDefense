## 확정 범위

- 단일 `Battle.unity` 재사용
- authoritative `BattleSessionContext.MapId`와 대소문자까지 정확히 일치하는 Profile만 적용
- State Authority가 `NetworkString<_16>` authoritative mapId를 최초 1회 고정하고 Client는 복제 완료 전까지 초기화 재시도
- 로컬 SessionContext mapId와 replicated authoritative mapId가 다르면 양쪽 모두 fail-closed
- `PlanetContentProfile` ScriptableObject에 환경 Prefab, 배경 Sprite/Color, 환경 Material, 조명, Particle/환경 Effect 참조 보관
- 환경 Prefab은 presentation-only로 제한
- Board, Lane, Waypoint, Wave Executor, Boss Runtime, Fusion `NetworkObject` 포함 금지
- 공통 Board/Lane/Waypoint/Boss 전투 구조 유지
- Additive Scene, 행성 고유 기믹, 신규 Boss 패턴, 별도 컷신 제외
- 알 수 없는 mapId와 누락·중복·비활성 Profile은 fallback 없이 Wave 시작 전에 fail-closed

## Editor 생성기

Unity MCP는 현재 isolated 프로젝트에서 실제 호출할 수 없어 Editor API 생성기를 사용한다.

```text
MyDefense.Battle.Editor.PlanetContentAssetGenerator.GeneratePlaceholderContent
```

생성 예정 에셋:

- `Assets/Resources/Battle/PlanetContent/PlanetContentCatalog.asset`
- `Assets/Resources/Battle/PlanetContent/Profiles/<MAP_ID>.asset` 9개
- `Assets/Prefabs/Battle/PlanetContent/<MAP_ID>_Environment.prefab` 9개
- `Assets/Prefabs/Battle/PlanetContent/<MAP_ID>_AmbientEffect.prefab` 9개
- `Assets/Materials/Battle/PlanetContent/<MAP_ID>_Environment.mat` 9개

`.prefab`, `.asset`, `.meta`, GUID는 Unity Editor API 생성기가 직접 관리했다. 1차 실행에서 같은 파일에 선언된 `PlanetEnvironmentContent`가 Prefab Missing Script로 탐지되어 fail-fast했고, MonoBehaviour를 전용 파일로 분리한 뒤 2차 실행에서 9개 전체 생성과 canonical 검증을 통과했다.

## 현재 위험

- placeholder는 최종 Asset이 아니므로 행성별 최종 가독성과 연출 품질은 비주얼 검증 대기다.
- production mapId 권위는 P1-5-7 Adapter 제공 전까지 local/dev 계약만 검증할 수 있다.
- 현재 Shared `BattleSessionSnapshot`에는 `mapId` 필드가 없다. roster → Fusion Session/Settlement의 불변성은 확인했지만 reconnect Snapshot까지의 불변 계약은 Shared 담당이 Snapshot schema를 확장한 뒤 완료할 수 있다. Battle 담당은 Shared 코드를 임의 수정하지 않는다.
- Camera/조명과 환경 Prefab 배치는 실제 `Battle.unity` 기준 해상도·카메라에서 사람 검증이 필요하다.
- 현재 Resources Catalog는 9개 행성 Prefab/Material을 직접 참조하고 초기화 때 전체 hierarchy를 동기 검증한다. 약 1.2MB placeholder 범위에서는 비차단이지만 최종 고용량 Asset 교체 시 Addressables 또는 검증 결과 캐시를 검토한다.

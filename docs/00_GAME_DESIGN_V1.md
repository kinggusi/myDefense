# 왹져 디펜스 기획서 V1

## 1. 게임 개요
- 장르: 2인 협동 머지 디펜스
- 클라이언트: Unity 6
- 실시간 네트워크: Photon Fusion
- 서버: Spring Boot
- 핵심 재미: 납치, 같은 종 머지, 신화 생체변이
- 용어:
  - 전투 중 소환: 납치(Kidnap)
  - 로비 영구 획득: 뽑기(Gacha)
  - 합성: Merge
  - 생체변이: Mutation
  - 유닛 명칭: Alien / 왹져

## 2. 전투 필드
- 플레이어별 4×6 필드, 총 24칸
- 왹져와 생체주입제 모두 1칸 차지
- 빈칸이 없으면 납치 불가
- 납치 결과는 화면 기준 왼쪽부터 오름차순으로 첫 빈칸에 자동 배치
- 왹져는 드래그로 빈칸 이동 가능
- B를 A에 드래그해 머지하면 결과물은 A 위치에 생성
- 두 플레이어 필드 사이에 공용 1자 전투 구역 존재
- 일반 몬스터는 각 플레이어 구역을 순환
- 보스는 공용 1자 구역에서 이동
- 보스 제한시간 초과 시 즉시 전체 패배

## 3. 플레이어 탈락
- 개인 필드 몬스터 수가 한도에 도달하면 해당 플레이어 탈락
- 탈락 플레이어는 모든 조작 비활성화 후 관전
- 탈락 플레이어 필드에 남은 몬스터는 제거하지 않음
- 해당 필드의 추가 몬스터 스폰만 중단
- 남은 플레이어가 기존 몬스터와 이후 보스를 처리
- 플레이어 탈락과 전체 경기 종료는 별도 상태로 관리

## 4. 왹져 구성
- 노말 8종
- 에픽 8종
- 유니크 8종
- 레전더리 8종
- 신화 4종
- 총 36종
- 노말~레전더리 각 등급 역할 구성:
  - 단일 공격 5종
  - 광역 공격 2종
  - 상태 이상 1종
- 모든 등급은 같은 종 + 같은 종만 머지 가능
- 머지 결과는 다음 등급 전체 풀에서 랜덤
- 레전더리 머지 시 각 플레이어가 해금한 신화 풀에서 랜덤
- 고정 진화 계보 없음

## 5. 납치
- 결과 확률:
  - 노말 왹져 99.5%
  - 생체주입제 0.5%
- 생체주입제 종류는 동일 확률
- 납치 비용은 시도할수록 증가
- 라운드가 바뀌어도 비용 초기화 없음
- 비용 공식은 밸런스 데이터로 관리

## 6. 생체주입제와 인자 계승
- 생체주입제는 원하는 변이를 확정하는 매개체
- 별도의 최종 형태가 아니라 랜덤 변이와 동일한 생체변이 결과를 만듦
- 노말~신화 모든 왹져에 사용 가능
- 주입제는 왹져 위로 드래그하여 사용
- 인자는 머지 후에도 계승
- 계승 규칙:
  - NONE + NONE → NONE
  - A + NONE → A
  - NONE + A → A
  - A + A → A
  - A + B → A 또는 B 중 하나 랜덤
- 서로 다른 인자 머지는 금지하지 않으며, 둘 중 하나만 남는 실수 유발 포인트로 사용

## 7. 생체변이
- 모든 Prefix는 노말~신화 모든 객체에 부착 가능
- 실제 변이 효과 발현 시점은 신화
- 주입 인자가 있는 신화:
  - 해당 인자의 변이 확정
- 주입 인자가 없는 신화:
  - 개인 인게임 골드 사용
  - 랜덤 변이
- 이미 변이된 신화:
  - 재변이 가능
  - 재변이 횟수에 따라 비용 증가
  - 같은 변이가 다시 나올 수 있음
- 주입제로 얻은 변이와 랜덤으로 얻은 같은 변이는 최종적으로 동일한 상태

## 8. 생체변이 8종 카테고리
각 변이는 아래 요소를 반드시 가짐:
- 강한 장점 1개
- 보조 장점 1개
- 명확한 단점 1개
- 공격 메커니즘 변화 1개
- 외형 변화 1개

초기 카테고리:
1. 광역형
2. 단일 보스형
3. 공격속도형
4. 도트 피해형
5. 경제형
6. 도박형
7. 상태 이상형
8. 꽝형

꽝형:
- 생체주입제로 직접 등장하지 않음
- 꽝 변이 2개를 모으면 아래 중 하나를 지급
  - 새로운 랜덤 신화
  - 랜덤 생체변이 신화
- 정확한 보상 비율은 밸런스 단계에서 결정

## 9. 외형 변화
생체변이 외형은 공통 변형 방식으로 시작:
- 몸 비율
- 색상
- 오라
- 장식
- 이펙트 크기
- 실제 판정 범위와 이펙트 크기는 별도 값으로 관리
- 모든 신화×변이 조합을 개별 프리팹으로 만들지 않음
- 공통 변형을 기본 적용하고, 극히 일부 조합만 예외 보정

## 10. 데이터 관리
기준 데이터 흐름:
Excel/CSV → JSON → Unity ScriptableObject 생성 → Spring Boot 밸런스 데이터

핵심 데이터:
- Alien
- Skill
- Mutation
- MutationInjector
- Monster
- Wave
- Economy
- BalanceConfig

Excel/CSV를 기준 원본으로 사용하고 Unity와 Spring Boot가 같은 JSON을 사용함.
